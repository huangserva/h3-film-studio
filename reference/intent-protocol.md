# 意图保全协议（INTENT Protocol）— 本 skill 的强制机制

> **存在理由**：模型会忘。用户说过的要求，隔几轮就丢，导致反复返工、用户重复第三遍。
> 这份协议把"记住用户要什么"变成**强制的文件操作**，不依赖记忆。

---

## 核心规则（三条，不许省）

### 规则 1：每个项目必须有 `INTENT.md`

项目一开始（用户提出需求的第一轮），就在项目目录建 `INTENT.md`：

```bash
mkdir -p <项目目录>
cp ~/.claude/skills/h3-film-studio/templates/INTENT.template.md <项目目录>/INTENT.md
```

它是**单一真相源**。用户的意图、判断标准、禁止事项，全部写在这里。

### 规则 2：用户每次纠正 → **立即**写进 `INTENT.md`

**触发条件**（出现任一，立刻写文件，不许等）：
- 用户说"我说过了" / "说过无数次" / "你又忘了" → **这是警报，说明已经丢过一次**
- 用户否定当前做法（"不对" / "很糟糕" / "不是这样"）
- 用户提出新的判断标准（"要有XX感觉" / "必须XX"）
- 用户纠正技术路线（"不要用XX" / "应该用XX"）

**写法**：追加到对应章节，用**用户的原话**做锚点，不要转译成自己的理解。

> ❌ 只在脑子里记住 → 三轮后必忘
> ✅ 立刻 Edit/Write 到 INTENT.md → 永久

### 规则 3：动手前先读

以下动作**之前**必须先 Read `INTENT.md`：
- 设计/修改分镜表
- 写生成 prompt
- 跑批生成
- 交付成片前自检

---

## `INTENT.md` 的结构（模板见 `templates/INTENT.template.md`）

| 章节 | 内容 |
|---|---|
| **人物设定** | 每个角色的本质、外形锁、行为边界（什么不能做） |
| **剧情铁律** | 必须有的环节、顺序、不许跳的过渡 |
| **技术铁律** | 用什么/不用什么（如"必须H3原声，禁TTS"）、参数纪律 |
| **判断标准** | 用户怎么算"好"（如"过渡要自然"、"要有守贞洁的感觉"） |
| **我反复犯的错** | 每次返工后追加一条，防止重犯 |

---

## 自检门（交付前必过）

生成/交付前，逐条对照 `INTENT.md` 自问：

- [ ] 人物设定有没有走样？（外形锁、行为边界）
- [ ] 剧情铁律有没有缺环节？（尤其"必须有的那一幕"）
- [ ] 技术铁律有没有违反？（用了禁用的东西？参数偷懒？）
- [ ] "我反复犯的错"那一节，这次犯了吗？

**任一条不过 → 不许交付，先修。**

---

## 为什么这样设计

- **文件 > 记忆**：模型的上下文会滚动、会压缩，文件不会。
- **原话 > 转译**：用户的原话保留了他真正在意的东西，我的转译会丢味道。
- **警报词是信号**：用户说"我说过了"，说明协议失效了一次 —— 必须当场补写，而不是道歉了事。
- **自检是硬门**：不自检就交付，等于让用户当 QA，他会累、会烦、会失去信任。
